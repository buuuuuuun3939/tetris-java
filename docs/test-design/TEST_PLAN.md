# Tetris テスト設計書（全体）

## 目的

この文書はテスト設計全体の方針と索引です。各機能の詳細な要件、前提条件、操作、期待結果は、機能別設計書で管理します。

仕様を変更するときは、関連する機能別設計書を先に更新し、その後テストコードと本体コードを変更します。

## テスト方針

- 盤面やミノなど、画面表示に依存しないロジックをJUnit 5の単体テストで検証します。
- 正常系に加えて、境界条件や複数要素の処理も確認します。
- ランダムな順番そのものではなく、ランダム処理でも必ず成立すべき性質を検証します。
- Swing描画、キー入力、タイマー、音声再生はロジックの単体テストと分けます。必要になった段階で結合テストまたは手動確認項目を設計します。
- テストは順序や実行環境に依存させず、`mvn test` で繰り返し同じ判定になるようにします。

## 実行環境

- Java 17以上
- Maven
- JUnit Jupiter 5.11.4
- 実行コマンド: `mvn test`

## 優先度と状態

- `P1`: 基本動作や回帰防止のため、優先して自動化するケース
- `P2`: 重要な境界条件や追加動作を確認するケース
- `P3`: 低頻度または補助的な確認ケース
- `実装済み・実行確認済み`: テストコードがあり、ユーザー環境で実行確認済み
- `未実装`: 設計済みだがテストコードはまだない

## 今後の対象候補

ゲーム進行（衝突判定、固定、HOLD、スコア、レベル、ポーズ、ゲームオーバー）は `GamePanel` にSwingタイマーや音声処理とともに実装されています。独立して安定した自動テストにする段階で、ロジックを画面処理から分ける方法も含めて設計します。

現在の対象外は、Swing画面の見た目、実際のキー入力から描画までの操作、音声再生、パッケージ化したmacOSアプリの起動です。
